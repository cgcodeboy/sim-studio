# 数据库设计说明书

## 1 引言

### 1.1 编写目的

本文给建库和实现程序 `RUN` 的人使用。概念结构是运行记录的数据模型。逻辑结构和物理结构用来建集合 `records`。

### 1.2 背景

库名 `simstudio`。数据库是 MongoDB 7，文档型。使用它的系统是仿真台。工程和元件库不是本程序的集合。

### 1.3 定义

活动运行：`active` 等于 1 的记录。版本：同一条记录上的 `revision`。请求号：开始命令的幂等键。控制请求号：暂停、继续、停止、改速度的幂等键。

### 1.4 参考资料

- `docs/框架设计.md`
- `docs/概要设计说明书.md`
- `docs/详细设计说明书.md` 程序 `RUN`

## 2 外部设计

### 2.1 标识符和状态

库标识 `simstudio`。集合标识 `records`。不是临时库。

### 2.2 使用它的程序

程序 `RUN`。接入不直接写这个集合。

### 2.3 约定

集合用复数名词。字段用驼峰。状态只允许 `running`、`paused`、`finished`、`interrupted`。

### 2.4 专门指导

插入、条件更新和清扫的顺序见详细设计第 3.6 节和第 3.7 节。日志确认之后调用才算成功。写关注是 `w:1`、`j:true`。

### 2.5 支持软件

MongoDB 7，文档模型。单节点，不建副本集，不做跨文档事务。不更换产品。

## 3 结构设计

### 3.1 概念结构设计

实体是运行记录。一份最终样本是它的值，没有单独的生命周期。

| 属性 | 标识 | 定义 | 类型 | 值域 | 可空 |
| --- | --- | --- | --- | --- | --- |
| 标识 | id | 这条记录的身份 | 字符串 | 非空 | 否 |
| 请求号 | requestId | 一次开始命令 | 字符串 | 非空，最长 128 | 否 |
| 工程 | projectId | 所属工程的标识，不是工程正文 | 字符串 | 非空 | 否 |
| 实验 | experimentId | 所属实验 | 字符串 | 非空 | 否 |
| 状态 | status | 生命周期 | 字符串 | 四个枚举值 | 否 |
| 速度 | speed | 本轮倍数 | 字符串 | `x1`、`x10`、`asap` | 否 |
| 来源 | source | 这次运行的主体标签 | 字符串 | `engine`、`dynamics`、`experiment` | 否 |
| 版本 | revision | 控制写入的令牌 | 整数 | 从 1 起，每次条件更新加 1 | 否 |
| 活动标记 | active | 占用唯一活动槽 | 整数 | 只有 1 | 非活动可空 |
| 控制请求号 | controlRequestId | 最近一次控制命令 | 字符串 | 最长 128 | 是 |
| 控制动作 | controlOp | 该请求号做成的动作 | 字符串 | `pause`、`resume`、`stop`、`speed` | 是 |
| 最终样本 | sample | 结束时的那一帧 | 文档 | 见下表 | 活动期间可空 |
| 更新时刻 | updatedAt | 最后一次写入 | 时间 | UTC | 否 |

样本：

| 属性 | 标识 | 定义 | 类型 | 值域 | 可空 |
| --- | --- | --- | --- | --- | --- |
| 模型时刻 | time | 这一帧的模型时间 | 数 | 不小于 0 | 否 |
| 序列 | series | 命名数值 | 列表 | 每项有名字、数值、来源 | 否 |
| 序列来源 | series.source | 这条数是谁算的 | 字符串 | `engine`、`dynamics`、`experiment` | 否 |
| 移动对象 | movers | 位置 | 列表 | 标识、坐标、朝向、是否忙碌 | 否 |
| 摄像机 | camera | 开始时抄入的姿态 | 文档 | 位置和目标 | 是 |
| 奖励 | reward | 实验各轮的目标 | 数的列表 | | 是 |

不变量放在运行记录上：一个请求号只有一条记录。`active` 等于 1 的记录全局只有一条。存量序列的来源不是 `engine`。队列序列的来源不是 `dynamics`。混合运行时 `source` 写 `engine`，存量只写在 `sample.series` 里且来源为 `dynamics`。活动期间 `sample` 为空，最终样本只在离开活动状态的那一次更新里写入。

关系：多条运行记录指向同一个工程标识。工程集合不在本文。没有从 `records` 指向工程的外键。删除工程时由模型程序调用 `RUN`，不在一次跨集合提交里完成。

### 3.2 逻辑结构设计

集合 `records`。由上面的实体直接成集合，不拆表。样本嵌在同一文档里，因为没有跨文档事务，结束更新必须一次写下状态和样本。

| 列 | 类型 | 可空 | 约束 |
| --- | --- | --- | --- |
| _id | string | 否 | 主键，存 id |
| requestId | string | 否 | 唯一 |
| projectId | string | 否 | |
| experimentId | string | 否 | |
| status | string | 否 | |
| speed | string | 否 | |
| source | string | 否 | |
| revision | int | 否 | 插入时为 1 |
| active | int | 是 | 部分唯一，只约束等于 1 的文档 |
| controlRequestId | string | 是 | |
| controlOp | string | 是 | |
| sample | document | 是 | |
| updatedAt | datetime | 否 | |

版本打在 `revision`，不打在 `status`。两次改速度都保持 `running`，只比较状态会让两个写入都成功。否决用 `_id` 当请求号：重复开始要返回已存在的那条，运行标识和请求号不是同一个值。否决另建锁集合：锁和记录会分成两次提交。

`active` 在插入 `running` 时写 1。暂停保持 1。变成 `finished` 或 `interrupted` 的同一次更新去掉该字段。

### 3.3 物理结构设计

| 索引 | 对应的查找或约束 |
| --- | --- |
| `_id` | 按运行标识读取，并作为条件更新的行 |
| `requestId` 唯一 | 重复的开始命令 |
| `active` 部分唯一，过滤条件为 `active` 等于 1 | 同时只能插入一条活动运行。清扫也按这个字段找出活动行 |
| `projectId` | 按工程删除；清扫之后找出悬挂记录 |

不为 `status` 再做索引。清扫已经走 `active`。当前代码里的 `status` 索引在实现时去掉。

访问方式都是按这些索引的单键查找或一次更新。没有表锁。两个开始命令同时插入时，后提交的那个在 `active` 唯一索引上失败。两个控制命令同时更新时，后提交的那个因 `revision` 不匹配而影响行数为 0。

外存设备和数据块大小不适用。架构没有给定磁盘型号，使用 MongoDB 数据卷的默认文件。缓冲不改变上述唯一约束。

### 4.2 安全保密设计

不适用。框架规定本轮没有登录。只有 `RUN` 所在进程连接数据库，集合所在端口不映射到宿主机。
